# 产品与技术方案


## 第三章  产品与解决方案

本章对应商业计划书的"产品与服务"章节、PPT 的第 4 页。写作要求：讲清楚"输入什么、输出什么、用户操作几步、比现状好在哪"。


### 3.1 产品定位

一句话定位：把"有益生物"从人工目测的模糊印象，变成连续、可核验、可计价的生态服务数据。

定位的三个关键限定，请在商业计划书中反复强调，避免评委误解为"又一个虫情测报设备"：

- 不做"又一个虫情测报设备"，做**唯一以有益生物为监测与服务核算主体**的系统。现有装备监测的是有害生物，我们监测的是"帮手"，这是主体上的差异，不是精度攀比。

- 不只识别个体，还负责把群落状态换算为**生态服务功能量与经济价值**。识别只是手段，能算清"这只蜂、这只瓢虫值多少钱"才是目的。

- 不止步于监测报表，还给出**可执行、可解释、可追溯**的调控决策。每条建议都能回答"依据是哪些观测、样本量多少、预期效果区间多宽"。


### 3.2 三层产品形态

| 层级 | 形态 | 面向用户 | 价值主张 |
|---|---|---|---|
| L1 内核 | 多模态识别与一致性融合引擎 + 生态服务核算模型（Python/C++ 核心，可作 SDK 与 API 输出） | 监测设备厂商、农业物联网平台、科研机构 | 被集成，形成生态壁垒 |
| L2 平台 | 边缘监测节点（声学 + 视觉 + 微气象 + 蜂箱传感）+ 云平台 + 手机 App | 种植主体、合作社、蜂授粉服务商、农业社会化服务组织 | 直接付费的主力产品 |
| L3 决策 | 生态服务价值核算报告 + 调控决策方案 + 证据链存证 | 地方政府（农业农村局 / 林草局）、认证机构、保险公司 | 高客单价、强专业壁垒 |

### 3.4 标准使用流程（PPT 建议用流程图呈现）

用户实际只需三步，采集与计算全部自动完成：

- 第一步·布点。按生境与作物布局部署边缘节点（太阳能 + 低功耗，田间立杆或树挂），手机 App 扫码绑定，自动完成时间同步与标定。

- 第二步·采集与识别。节点本地完成轻量推理，结果经 LoRa / 4G 回传云端；云端执行跨模态一致性融合与群落指标计算，在网页与 App 端生成实时看板。

- 第三步·核算与决策。一键生成生态服务价值核算报告与调控建议；每条结论都可下钻查看其证据模态、样本量与置信区间。

关键对比：现状是"一年几次人工样方 + 专家目测 + Excel 静态当量估算"，链路长、频次低、结果与实际生物状况脱钩；本产品是"7×24 连续观测 + 多模态互证 + 可标定服务核算 + 可执行决策"，一条链路、自动完成。

## 第四章  技术方案

本章对应商业计划书的"技术与研发"章节、PPT 第 4–6 页。写作要求：让技术评委相信方法成立，让非技术评委相信学生团队做得出来。


### 4.1 统一理论内核：从"证据链"到"一致性 + 供给函数"

这是项目最重要的理论贡献，建议在商业计划书中用一整页专门说明。

观察：有益生物的监测与生态服务核算，本质上是一条**证据链**。从最底层的传感器信号，到最终的管理决策，中间隔着四级映射，而每一级都存在缺口：

```
观测模态 → 生物事件 → 群落状态 → 服务功能量 → 经济价值 → 管理决策
声/图/气象  个体与计数  多样性与结构  授粉/害虫调控  价值区间  措施清单
   └缺口一┘    └缺口二┘    └缺口三┘    └缺口四┘
```

现有技术各自只填补其中一小段：声学设备解决"有无声音"，测报灯解决"有无虫子"，当量因子法解决"给个数字"。没有任何方法把这条链整体打通，并让每一级的误差可传递、可解释。

本项目给出两个核心构造，把这条链变成一个可计算的整体。


#### 构造一：跨模态观测一致性

核心判断：同一个生物事件，会被多个模态同时观测到，而这些观测之间必须互相"可预测"。一致性既是融合的依据，也是异常检测的依据。

```
C(e) = Σ_m  w_m · d_m( o_m(e) , p_m(e) )

其中：e 为生物事件；o_m(e) 为模态 m 对该事件的观测值；
      p_m(e) 为由其余模态预测出的模态 m 的值（predicted）；
      w_m 为模态权重；d_m 为距离度量。
      C(e) 越小，表示该事件的跨模态观测越自洽。
```

| 物理含义 | 举例 | 用途 |
|---|---|---|
| 一致性高 → 提升置信 | 蜜蜂出巢高峰同时表现为：蜂箱声学能量上升、蜂箱重量下降、访花视频计数上升、微气象适宜 | 多模态证据融合，降低单模态误报 |
| 一致性极低且无生态解释 → 伪观测 | 大风导致草木晃动触发了"访花"视觉检测，但声学与称重均无对应信号 | 自动剔除伪观测，减少人工复核 |
| 长期一致性漂移 → 系统自校验 | 某节点声学与视觉的一致性随时间系统性下降 | 提示传感器故障或标定失效，保证长期数据可信 |

这个构造的价值在于"一个度量、三种用途"：它同时解决了融合、纠错与系统可信度三个问题，而不是三套独立机制。


#### 构造二：生态服务供给函数

核心判断：生态服务不是按土地面积查表得来的常数，而是由生物群落状态、生境条件与管理措施共同决定的**可标定函数**。

```
S_k = g_k( Q , H , M )      k ∈ {授粉服务, 害虫调控服务}

Q：有益生物群落状态（功能群密度、多样性、天敌与害虫之比）
H：生境条件（蜜源植物、花带、非作物生境比例、景观格局）
M：管理措施（施药种类与时机、耕作方式、天敌释放、蜂群投放）
```

决策目标为在约束下最大化净收益：

```
max   Σ_k  v_k · S_k(Q, H, M)  −  Cost(M)

s.t.  Q 的生物多样性指数不低于阈值（保护底线）
      农药用量不超过上限（政策约束）
      措施成本在预算内，且措施在当地可执行（可行性约束）
```

三个构造共用同一套"证据链"数据结构：一致性度量负责让证据可信，供给函数负责把证据换算成价值，决策优化负责在价值与约束之间做权衡。这是把割裂的"监测—核算—决策"三个环节变成一个连续问题的关键，也是项目的立论基础。


### 4.2 技术架构：五层处理管线

数据从 L0 感知层进入，依次经过 L1 识别、L2 群落、L3 服务、L4 决策四个处理层，逐层向上抽象。

| 层级 | 名称 | 核心职责 | 关键输出 |
|---|---|---|---|
| L0 | 感知层 | 声学节点（MEMS 麦克风阵列）、视觉节点（定时成像 / 短视频）、微气象、蜂箱传感（称重、巢内温湿度、巢内声）；可选接入气象与遥感数据 | 多模态原始信号与元数据 |
| L1 | 识别层 | 单模态识别（声学事件检测与分类、视觉检测与计数）+ 跨模态一致性融合与校验 | 带置信度与不确定度的生物事件 |
| L2 | 群落层 | 时间序列聚合；计算多样性指数与功能群结构、日活动节律；结合生境与管理因子做归因分析 | 群落状态指标 + 归因结论 |
| L3 | 服务层 | 代入生态服务供给函数，计算授粉服务与害虫调控服务的功能量；按价值系数换算为经济价值，并完成不确定度传递 | 服务功能量 + 价值区间 |
| L4 | 决策层 | 在多样性底线、农药上限、成本预算约束下求解多目标优化；输出帕累托前沿与措施组合建议，附证据链 | 调控建议 + 可追溯报告 |

架构的核心设计意图：L1 与 L3 之间不是单向流水线，而是共享同一个**证据链对象**——每个生物事件携带"来自哪些模态、一致性多少、置信度多少"，这个对象在向上聚合时被打包传递，最终出现在决策报告里。这正是"每条结论都可追溯"的工程实现方式。


### 4.3 关键技术模块

| 模块 | 技术路线 | 说明 |
|---|---|---|
| 声学事件检测与分类 | 时频特征（梅尔谱 / 小波）+ CRNN 或 CNN 分类；昆虫飞行声翅频差异、鸟鸣迁移学习、蜂群声异常检测（分蜂、失王、巢虫） | 非目标噪声（风声、水流、农机）需专门的拒识类 |
| 视觉识别与计数 | YOLO 系列轻量化检测 + 多目标跟踪；黄板 / 蓝板定时成像计数；花朵访花昆虫短视频识别；红外相机益鸟识别 | 小目标密集遮挡是主要难度，需针对性地做数据增强 |
| 跨模态一致性融合 | 贝叶斯 / 证据理论（Dempster-Shafer）融合，配合一致性校验；输出经校准的置信度 | ★ 项目核心算法，也是创新点一 |
| 边缘—云协同 | 节点本地轻量推理（RKNN / TensorRT）+ 云端重模型与融合；低带宽回传（LoRa / 4G Cat-1） | 决定单节点成本与续航，是工程可行性的关键 |
| 群落与生境分析 | 多样性指数、功能群比例、时空格局分析；广义线性混合模型（GLMM）做管理措施效应归因 | 生态学统计方法的工程化封装 |
| 生态服务核算 | 授粉服务：访花频次与传粉者密度 → 坐果率 / 单果重响应曲线 → 产值；<br>害虫调控：天敌与害虫之比 → 捕食潜力 → 避免损失；<br>以当量因子法作为对照基线，显示两者差异 | ★ 项目核心算法，也是创新点二；响应曲线必须用田间试验标定 |
| 决策优化 | 多目标约束优化（加权 / 帕累托前沿）；输出措施组合与预期效果区间 | 创新点三；要求结论可解释、可执行 |
| 可解释与可追溯 | 每条结论标注证据模态、样本量、置信区间、置信来源与时间戳 | 直接回应"我凭什么信这个数" |
| 数据合规与安全 | 仅采集非人目标与环境数据；地理坐标脱敏；农户数据授权、用途限定、可删除；提供完全离线的本地模式 | 答辩必问项，必须在 BP 中写明 |


### 4.4 技术栈与可行性

技术策略：通用能力使用成熟开源模型与组件兜底，创新火力集中于"有益生物的多模态监测"与"生态服务核算"两个环节。这一策略同时保证工程可靠性、开发速度与创新集中度。

| 模块 | 选型 | 选用理由 |
|---|---|---|
| 声学采集 | MEMS 麦克风阵列 + 低功耗采集板（ESP32-S3 / RK 系列） | 成本低、功耗可控、可批量部署 |
| 视觉采集 | 低功耗摄像头模组 + 定时 / 触发成像 | 功耗与成本最优 |
| 边缘计算 | 瑞芯微 RK3576 / RK3588（内置 NPU）或 Jetson Orin Nano | 国产化、NPU 算力够用、生态成熟；团队已有同系列平台经验 |
| 通信 | LoRa（近距离组网）+ 4G Cat-1（远端回传）+ NB-IoT（备选） | 覆盖与功耗的平衡 |
| 供电 | 太阳能板 + 锂电，目标连续无维护 ≥ 30 天 | 田间部署的硬要求 |
| 云平台 | Python / FastAPI + PostgreSQL + PostGIS + TimescaleDB + 对象存储 | 时序与空间数据是核心负载 |
| 模型训练与部署 | PyTorch + Ultralytics(YOLO) + torchaudio / librosa；ONNX 与 RKNN 部署到边缘 | 主流生态，资料与社区支持充分 |
| 生态统计 | R（vegan、lme4）+ Python（statsmodels） | 生态学领域标准工具 |
| 服务核算 | 自研生态服务供给函数 + 当量因子法对照基线 | 创新点二的实现载体 |
| 应用端 | 微信小程序 / App（uni-app 或 Flutter）+ Web 看板（Vue / React） | 种植户与蜂农的使用习惯以手机为主 |

团队技能门槛：核心研发需要"声学信号处理 + 计算机视觉 + 嵌入式硬件 + 生态学统计"的组合。本项目通过团队配置正面回应这一门槛，并对少数高门槛环节（分类学鉴定）明确采用"功能群级识别"策略绕开，不回避。


### 4.5 技术指标的承诺边界

以下边界必须主动声明。主动说明比被评委问出来更可信。

- 不承诺"物种级"精确鉴定。系统定位为**功能群级**识别（传粉者、捕食性天敌、寄生性天敌、益鸟）。仅对少数形态易辨识的类群提供物种级结果，疑难类群明确建议人工或分子复核。

- 不承诺绝对计数。声学与视觉计数输出的是**相对丰度指数**，必须经人工标定后换算；所有结果一律附带置信区间。

- 生态服务价值不是"真值"。它是"基于实测生物数据的可标定估计"，必须报告不确定度与所依赖的假设，这也是它能被审计的前提。

- 决策建议不替代农技专家。系统输出的是建议清单与预期效果区间，最终决策权在使用者手中。
