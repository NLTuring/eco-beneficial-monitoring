# 商业计划书设计纲要


## 前言  本纲要怎么用

本文档回答一个问题：项目的事实、数据与论证都已经在《项目简介文档》里了，商业计划书该怎么组织？它与《项目简介文档》附录 A 的分工是——附录 A 只告诉你"哪一章取用哪一节"，本纲要进一步告诉你每一章"要回答什么问题、必须放什么内容、要出哪张图、占多少篇幅、评委在这里看什么、最容易在哪里失分"。


### 0.1 三个可信：评委到底在读什么

一份商业计划书要在有限时间里让评委相信三件事，缺一件就会掉档：

- **机会可信**：这个问题真实存在、规模足够大，而且现在做正当时——而不是三年前或三年后。

- **团队可信**：这支队伍具备把这件事做成所需的能力组合，并且已经动手做了（有原型、有数据、有访谈）。

- **路径可信**：钱从哪里来、怎么一步步滚起来、最坏情况怎么办。

因此全篇的结构设计要服务于这三件事，而不是"把项目讲全"。凡是无法归入这三件事的内容，都应该删掉或挪进附录。


### 0.2 商业计划书与申报书不是同一份材料

这是最容易做错的一件事：把申报书换个封面就当商业计划书交上去。两者的评审逻辑完全不同。

| 维度 | 申报书（大挑） | 商业计划书（小挑） |
|---|---|---|
| 回答的核心问题 | 这个技术是否先进、是否原创 | 这门生意是否成立、能否长大 |
| 主角 | 技术方案 | 客户与钱 |
| 技术章节的处理 | 重点章节，可占三成篇幅 | 压缩到两成以内，只讲"为什么别人做不出来" |
| 证据偏好 | 论文、专利、查新报告、第三方测试 | 访谈记录、合作意向书、付费意愿、实测数据 |
| 语气 | 严谨克制 | 明确、有判断、敢下结论 |
| 典型失败信号 | 技术讲不清楚 | 通篇在讲技术，没有客户和收入 |

一句话：申报书证明"我们能做出来"，商业计划书证明"有人愿意付钱，而且这件事能规模化"。本项目天然是技术驱动型项目，因此小挑材料的最大风险恰恰是**写成技术说明书**。


### 0.3 三条写作纪律

- 第一，每一个结论后面必须跟一个数字、一个案例或一份可复现的证据。评委记住的永远是数字，不是排比句。

- 第二，所有数据都要能回答"从哪里来、谁在什么时间用什么方法得到的"。标注 ★ 的数据在完成核实之前，不得写入正式提交版本。

- 第三，主动暴露风险与能力边界。"这一步我们还没做过，计划用某种方式解决"比"我们没问题"可信得多。

## 第一章  总体设计


### 1.1 篇幅与结构预算

下表是建议的篇幅分配。多数学校与省级比赛对页数有上限，**一律以学校团委发布的模板为准**；若上限更严，优先压缩第四、八、十一章，绝不动第二、五、七、十章（这四章决定分值）。

| 章节 | 建议页数 | 建议字数 | 必配图表 |
|---|---|---|---|
| 封面 / 目录 | 各 1 页 | — | 系统全景缩略图 |
| 执行摘要 | 1 页 | 600–800 字 | "一页看懂"图或关键数字条 |
| 一、项目概述与愿景 | 1.5 页 | 800–1000 字 | 系统全景图 |
| 二、痛点与市场机会 | 3 页 | 1500–2000 字 | 装备对比图、诱集物照片、政策时间轴 |
| 三、产品与服务 | 3 页 | 1500–2000 字 | 产品体系图、使用流程图、功能价值表 |
| 四、技术方案与知识产权 | 2.5 页 | 1200–1600 字 | 五层架构图、创新点指标对照表 |
| 五、市场分析 | 3 页 | 1500–2000 字 | 客户分层表、规模测算表、滩头图 |
| 六、竞争分析 | 2 页 | 1000–1300 字 | 竞品矩阵、四层壁垒图 |
| 七、商业模式 | 3 页 | 1500–2000 字 | 商业画布、收入结构图、增长飞轮 |
| 八、营销与运营 | 2 页 | 1000–1300 字 | 获客漏斗图、交付运维流程图 |
| 九、团队 | 2 页 | 800–1000 字 | 团队构成表、能力匹配矩阵 |
| 十、财务分析 | 3 页 | 表格为主 | 成本表、单位经济表、三年预测、盈亏平衡图 |
| 十一、风险与应对 | 1.5 页 | 800–1000 字 | 风险—概率—影响矩阵 |
| 十二、发展规划与融资需求 | 2 页 | 800–1000 字 | 三阶段路线图、里程碑甘特图、资金用途 |
| 附录 | 不限 | — | 以表格与清单为主 |
| 合计（正文） | 32–36 页 | 约 1.6 万–2 万字 | 约 15 张图 + 20 张表 |


### 1.2 叙事主线：一条线，五个转折

全篇只讲一条故事线。每一章都要能回答"我在故事线的哪一环"；**如果某一章无法归位，它大概率不该出现在正文里。**

```
① 偏斜：整个监测体系都在盯害虫，真正决定产量与生态安全的"帮手"没人测
        ↓
② 代价：不测就看不见——授粉不足与天敌不足无法预警；
        更要命的是生态服务的价值算不出来，保护生态的人拿不到回报
        ↓
③ 答案：用跨模态观测一致性把"帮手"变成可信数据，
        再用生态服务供给函数把数据变成钱
        ↓
④ 生意：谁付费、付多少、怎么滚起来
        （硬件铺得下去 → 平台收得回来 → 服务赚得到钱 → 数据锁得住客户）
        ↓
⑤ 凭什么：数据壁垒 + 计量口径 + 垂直场景，以及团队已经动手做了什么
```


### 1.3 阅读动线：评委不会按顺序读

真实的阅读动线通常是：封面 → 执行摘要 → 随便翻到的图表 → 财务 → 团队 → 结论。因此有三条硬要求：

- 执行摘要必须能**独立成立**——假设评委只读这一页，他也要能明白全部结论。

- 每一张图表必须能**脱离正文被看懂**——图题写结论，不要写"图 3-1 产品架构"这种名词式标题。

- 财务与团队两章要经得起翻，因为这是被翻到概率最高的两章。


### 1.4 与《项目简介文档》的对应关系

| 商业计划书章节 | 取用《项目简介文档》 | 主要工作 |
|---|---|---|
| 执行摘要 | 1.2 四种长度简介 | 取标准版或详版，压缩到 800 字内，补一句收入模式与资金需求 |
| 一、项目概述与愿景 | 1.1、1.2、3.2 | 用"一句话定位 + 三层产品形态"重写，补三年里程碑 |
| 二、痛点与市场机会 | 第二章 | 三层痛点按"现象—证据—代价"重排，每层后紧跟数字 |
| 三、产品与服务 | 第三章 | 补上"客户拿到手的第一周会发生什么" |
| 四、技术方案与知识产权 | 第四章、第五章、第十三章 | 大幅压缩：只留统一理论内核 + 四条创新点 + 知识产权清单 |
| 五、市场分析 | 第七章 | 把测算框架填成真数（★ 必须自测） |
| 六、竞争分析 | 第六章 | 竞品矩阵 + 差异化定位一句话 + 四层壁垒 |
| 七、商业模式 | 第八章 | 画布 + 四层收入 + 定价对照 + 飞轮 + 合规声明 |
| 八、营销与运营 | 8.1 渠道与客户关系、7.3 滩头战略 | 本纲要新增的一章：把渠道、获客、交付与运维拆开写成可执行的动作 |
| 九、团队 | 第十章 | 团队表 + 优势 + 主动说明能力缺口与弥补方案 |
| 十、财务分析 | 第九章 | 补齐真数（★），新增盈亏平衡与资金用途 |
| 十一、风险与应对 | 第十二章 | 直接取用，补一条财务风险 |
| 十二、发展规划与融资需求 | 第十一章 | 补资金用途、里程碑与下一轮进入条件 |
| 附录 | 附录 C、附录 D | 问答索引、素材清单、访谈记录、试验原始数据 |

相比《项目简介文档》附录 A，本纲要做了两处调整：把"技术方案"与"创新点"合并为第四章（商业计划书里技术不必占两章），把"营销与运营"独立成章（小挑评审关注落地转化）。若目标是"大挑"，把第四章还原为重点章、把第八章折叠进第七章即可。


### 1.5 一条内容线，两种材料形态

技术材料与商业材料应当共用同一批事实与数据，只在组织方式与详略上分叉。这样可以避免两套材料互相矛盾——这是评委最容易发现的硬伤。

| 内容块 | 大挑（技术材料） | 小挑（商业计划书） |
|---|---|---|
| 核心理论 | 完整展开，可含公式与算法细节 | 一页讲完，只留"为什么这是新的" |
| 四级创新点 | 逐条论证 + 消融实验 | 逐条三句话 + 量化指标 |
| 市场部分 | 压缩为"应用前景"半页 | 展开为完整测算与滩头战略 |
| 财务部分 | 删去 | 完整保留并做敏感性分析 |
| 附录重点 | 实验数据、第三方测试报告 | 访谈记录、合作意向、财务测算明细 |

## 第二章  逐章设计规格

本章是全文核心。每一章给出一张规格表：这一章要回答的问题、必须出现的内容、必须出现的图表、素材来源、篇幅预算、评分点与常见失分点。写作时把规格表当作验收标准，逐项打钩。


### 2.1 封面与目录

| 设计项 | 规格 |
|---|---|
| 要回答的问题 | （三步之内建立专业感，不做论证） |
| 必须出现的内容 | ① 项目名称 + 一句话定位；② 团队名称、学校院系、项目负责人、指导教师；③ 联系方式；④ 自动目录（页码与正文一致） |
| 必须出现的图表 | 封面可放一句定位语与一张系统缩略图 |
| 素材来源 | —（封面与目录为形式页，不取用正文素材） |
| 篇幅预算 | 各 1 页 |
| 评分点 | 材料完整度与专业印象 |
| 常见失分点 | ① 封面缺联系方式；② 目录页码与正文不符（手工目录最易出错，务必用自动目录并在提交前更新域）；③ 封面残留"初稿""内部资料"等字样 |


### 2.2 执行摘要

| 设计项 | 规格 |
|---|---|
| 要回答的问题 | 假设评委只读这一页，他能否明白全部结论？ |
| 必须出现的内容 | 五句话结构：① 我们在解决什么问题（一句话 + 一个数字）；② 我们做了什么（产品定义）；③ 凭什么我们能做（关键能力或已有证据）；④ 生意怎么成立（客户 + 收入模式 + 定价对照）；⑤ 需要什么（资金 / 资源 / 合作） |
| 必须出现的图表 | 一张"一页看懂"图，或五个关键数字的数据条 |
| 素材来源 | 《项目简介文档》1.2（标准版或详版）+ 第八章 |
| 篇幅预算 | 1 页，600–800 字 |
| 评分点 | 全篇印象分，实际权重远超其篇幅 |
| 常见失分点 | ① 写成背景介绍，读了半页还不知道卖什么；② 通篇没有数字；③ 与正文口径不一致（摘要写 3500 元、正文写 1999 元） |


### 2.3 第一章  项目概述与愿景

| 设计项 | 规格 |
|---|---|
| 要回答的问题 | 你们到底做什么？为什么现在做？ |
| 必须出现的内容 | ① 一句话定位（不超过 25 字，全篇反复出现）；② 产品是什么（三层形态：监测节点 / 云平台 / 核算服务）；③ 时机窗口（政策、技术、数据积累三条同时成熟）；④ 三年阶段目标——不是愿景口号，是可检验的里程碑 |
| 必须出现的图表 | 一张系统全景图：田间节点 → 云端融合 → 核算报告 → 决策建议 |
| 素材来源 | 《项目简介文档》1.1、1.2、3.2 |
| 篇幅预算 | 1–1.5 页，800–1000 字 |
| 评分点 | 项目定位清晰度、机会判断力 |
| 常见失分点 | ① 用"打造国内领先的……平台"这类口号代替产品定义；② 把愿景当目标（"成为行业第一"不是里程碑）；③ 一上来就讲技术原理 |


### 2.4 第二章  痛点与市场机会

| 设计项 | 规格 |
|---|---|
| 要回答的问题 | 这个问题是真的吗？有多大？为什么现在做正当时？ |
| 必须出现的内容 | ① 三层痛点，每层后面紧跟一个数字或一个可复现的案例（只盯害虫 / 人工测不准测不起测不勤 / 生态服务算不清）；② 政策与市场驱动力（减药增效、GEP 核算、生态补偿、绿色认证）；③ 时机窗口论证——为什么不是三年前，也不是三年后 |
| 必须出现的图表 | ① 现状监测装备对比图（说明"全在盯害虫"）；② 诱虫灯与黄板诱集物中天敌与传粉者占比的照片（★ 成本最低、冲击力最强）；③ 政策时间轴 |
| 素材来源 | 《项目简介文档》第二章、2.5 证据清单 |
| 篇幅预算 | 3 页，1500–2000 字 |
| 评分点 | 商业价值——全篇分值最高的两章之一 |
| 常见失分点 | ① 只有形容词没有数字；② 用第三方报告的大数字撑场面，不讲自己的调研；③ 把技术痛点当商业痛点——评委只关心"谁因此损失了钱" |


### 2.5 第三章  产品与服务

| 设计项 | 规格 |
|---|---|
| 要回答的问题 | 你们卖给客户的是什么？他用完之后和现在有什么不同？ |
| 必须出现的内容 | ① 三层产品形态与各自的客户；② 客户视角的价值（授粉不足可提前发现、天敌与害虫比可量化、生态服务价值可核算可审计）；③ 交付形态与使用流程（布点 → 采集识别 → 核算决策三步）；④ 产品路线图（P0–P4，标注哪一阶段可现场演示） |
| 必须出现的图表 | ① 产品体系图（三层）；② 使用流程图（三步）；③ 核心功能与用户价值对照表 |
| 素材来源 | 《项目简介文档》第三章、11.1 |
| 篇幅预算 | 3 页，1500–2000 字 |
| 评分点 | 产品定义能力、客户价值清晰度 |
| 常见失分点 | ① 用功能列表代替价值描述（"支持 10 种识别"不如"授粉不足提前 3 天预警"）；② 说不清客户第一天拿到手会发生什么；③ 把"系统能做很多事"当优点，缺乏取舍 |


### 2.6 第四章  技术方案与知识产权

| 设计项 | 规格 |
|---|---|
| 要回答的问题 | 为什么别人做不出来？你们的护城河是技术还是别的东西？ |
| 必须出现的内容 | ① 统一理论内核（跨模态观测一致性 + 生态服务供给函数），一页讲完；② 四条创新点，每条用"现有做法失败在哪 + 我们怎么做 + 量化指标"三句话；③ 知识产权清单（专利、软著、论文、数据集）；④ 技术边界声明（不做物种级鉴定、不承诺绝对计数） |
| 必须出现的图表 | ① 系统五层架构图；② 创新点与现有方案的指标对照表 |
| 素材来源 | 《项目简介文档》第四章、第五章、第十三章 |
| 篇幅预算 | 2–2.5 页，1200–1600 字（严格上限） |
| 评分点 | 创新性与技术可行性 |
| 常见失分点 | ① 写成技术说明书，一章占掉全篇三成篇幅；② 只讲用了什么模型，不讲"为什么这是新的"；③ 不声明能力边界，被追问时无法收场 |


### 2.7 第五章  市场分析

| 设计项 | 规格 |
|---|---|
| 要回答的问题 | 这个市场有多大？你们先打哪一块？ |
| 必须出现的内容 | ① 客户分层（种植主体 / 蜂农与授粉服务商 / 政府部门 / 认证与保险机构）；② 自下而上的规模测算（客户基数 × 节点数 × 可触达比例 × 付费率 × 客单价），写明每一个假设的来源；③ 滩头市场选择与理由；④ 三年拓展路径 |
| 必须出现的图表 | ① 客户分层表；② 规模测算表（含假设与来源）；③ 滩头战略三阶段图 |
| 素材来源 | 《项目简介文档》第七章 |
| 篇幅预算 | 3 页，1500–2000 字 |
| 评分点 | 市场前景——分值最高的一章 |
| 常见失分点 | ① 引用"万亿级市场"却不解释与自己有什么关系；② 只给结论数字，不写测算过程；③ 想服务所有客户，没有取舍 |


### 2.8 第六章  竞争分析

| 设计项 | 规格 |
|---|---|

## 第三章  数据与证据的取证计划

写作顺序上有一条铁律：**先取证，后写作**。数据没到位就开始写正文，最后必然返工——因为结论会随数据变化。本章的清单就是取证任务的来源。


### 3.1 必须自己跑出来的数据（★ 最高优先级）

| 数据项 | 方法 | 成本 | 用途 | 状态 |
|---|---|---|---|---|
| 诱虫灯与黄板诱集物中天敌与传粉者的占比 | 绿色防控示范区实地诱集 + 分类拍照记录 | 1 天，极低 | 支撑"只盯害虫且误伤帮手"，答辩核心素材 | 【待完成】 |
| 人工调查的工时与成本 | 跟随植保站或自行完成一次完整样方调查并全程计时 | 1–2 天 | 支撑"测不起、测不勤" | 【待完成】 |
| 授粉服务对照试验 | 示范区设对照区与处理区，记录传粉者密度、访花频次、坐果率 | 一个生长季 | 支撑核心创新点与财务预测 | 【待完成】 |
| 竞争方案实测 | 同一地块、同一时段，人工调查方案与设备方案对照 | 数天 | 支撑竞争分析 | 【待完成】 |
| 用户访谈（3–5 家） | 半结构化访谈，保留录音与记录表 | 1 周 | 支撑付费意愿与定价 | 【待完成】 |
| 节点续航实测 | 真实田间连续工作测试，记录功耗与故障 | 1 个月 | 支撑技术可行性 | 【待完成】 |


### 3.2 必须核实的引用数据

《项目简介文档》附录 E 已逐条列出所有待核实数据及其核实方法。原则很简单：**每一条进入正式材料的数据，都必须能回答"这个数字从哪里来、谁在什么时间用什么方法得到的"。**标注 ★ 的条目在核实完成之前，宁可在文中删去，也不要用模糊表述带过。


### 3.3 证据分级：什么证据放在哪里

| 证据类型 | 可信度 | 在材料中的位置 |
|---|---|---|
| 自测数据（田间试验、实测、录屏） | 最高 | 正文直接引用 + 附录放原始记录 |
| 用户访谈与合作意向书 | 高 | 正文引用结论 + 附录放原件与录音 |
| 政府公开统计与政策文件 | 高 | 正文引用（必须标注文号与年份） |
| 公开数据集与学术文献 | 中 | 正文引用（标注出处与年份） |
| 第三方报告的大数字 | 低 | 仅作背景铺垫，不得作为决策依据 |


### 3.4 访谈提纲模板

三类对象的访谈重点不同。**访谈的价值不在于"对方说这个痛点很痛"，而在于拿到可引用的原话、可量化的损失、以及可验证的付费意愿。**

| 访谈对象 | 必问问题（择要） |
|---|---|
| 种植主体 / 园区负责人 | ① 去年授粉季有没有出现授粉不足？怎么发现的？损失大概多少？<br>② 现在怎么判断天敌够不够？多久看一次？<br>③ 如果有一套系统能提前预警并给出施药建议，你愿意按年付费吗？能接受的价格区间是多少？<br>④ 谁来决定买不买？决策需要多久？ |
| 蜂农 / 蜂授粉服务商 | ① 有没有遇到过"放了蜂但种植户说没效果"的争议？最后怎么解决？<br>② 如果能出一份客观的授粉效果报告，对你的生意有帮助吗？<br>③ 你愿意为这份报告付多少钱？ |
| 地方政府（农业农村局 / 林草局 / 植保站） | ① 生态补偿或 GEP 核算目前的数据来源是什么？可靠性如何？<br>② 建设监测网络通常通过什么渠道采购？预算规模与周期？<br>③ 有没有正在推进的相关项目可以对接？ |

### 4.2 制图规范

- **图题写结论，不写名词。**"图 5 产品三层形态与对应客户"优于"图 5 产品架构图"。评委看图题就应该明白这张图要证明什么。

- 单色系或双色系，不使用 3D 图表、渐变与阴影。数据图必须标注单位与来源。

- 图内字号不小于正文的 80%，保证投影后仍可读。

- 每张图必须在正文里被引用一次，并在引用处给出结论——不要让评委自己去图里找。

- 表格的表头加粗，跨页时表头自动重复；表题在表上方，图题在图下方。

## 第五章  制作流程与时间表


### 5.1 六步成稿流程

```
① 定结构：按第二章的规格表搭出全部标题（此时正文为空）
        ↓
② 填数据：先完成第三章的取证任务，把数字填进表格
        ↓
③ 出图：按第四章清单完成约 20 张图，先图后文
        ↓
④ 写正文：对着规格表逐章写，每段只服务一个结论
        ↓
⑤ 通读删减：删掉所有无法归入"三个可信"的内容，压缩第四、八、十一章
        ↓
⑥ 形式统稿：统一字体字号、更新目录域、核对图表编号与交叉引用
```

第 ② 步与第 ③ 步的顺序不能颠倒。**先把数据与图做出来，文字自然就写得快；反过来则一定反复返工。**

## 附录  低分与退稿原因清单

以下十五条是从实际评审反馈中归纳的高频问题，交稿前逐条对照。

| 序号 | 问题 | 后果 |
|---|---|---|
| 1 | 通篇在讲技术，没有客户、没有收入模式 | 被判定为"技术说明书"，直接掉档 |
| 2 | 用第三方报告的万亿级市场数字撑场面 | 被追问"与你有什么关系"时崩盘 |
| 3 | 编造精细的收入预测 | 一问细节就崩，且被视为不诚信 |
| 4 | 只有形容词没有数字（"手段落后""效率低下"） | 评委无法验证，印象分归零 |
| 5 | 声称没有竞争对手 | 等于说这个市场不存在 |
| 6 | 愿景当目标（"成为行业第一"） | 被认为缺乏战略判断力 |
| 7 | 收入只有一条线，没有放大逻辑 | 商业模式创新项失分 |
| 8 | 定价没有依据，也未与替代方案比较 | 被认为不熟悉真实市场 |
| 9 | 回避风险与能力缺口 | 被视为不成熟或不懂装懂 |
| 10 | 里程碑不可检验（"完成产品迭代"） | 被认为没有可执行的计划 |
| 11 | 忽略农业季节性，试验安排在非生长季 | 暴露对行业缺乏基本了解 |
| 12 | 摘要与正文数字口径不一致 | 被认定为材料不严谨 |
| 13 | 附录堆砌材料，正文引用却找不到出处 | 证据链断裂 |
| 14 | 目录页码与正文不符、存在残页空页 | 形式分与专业印象受损 |
| 15 | 数据合规问题未说明 | 答辩被追问时无法收场 |
